# Научная защита: оценщик, правильность и калибровка

Исследовательский вопрос: сохраняет ли оценщик предпочтение правильного ответа при изменении порядка, многословия и уверенного тона? `study.py` создаёт оригинальные задачи с проверяемыми ответами, меняет только риторическое оформление кандидатов и сохраняет решения отдельно для каждого условия.

## Что вычисляет модель

У генеративного оценщика берутся два логита следующего токена: z_A и z_B. Вероятность A условно на выборе между этими токенами равна exp(z_A)/(exp(z_A)+exp(z_B)). Это не вероятность того, что свободная генерация вообще выдаст A: масса всех остальных токенов исключена. Поэтому здесь нет показателя ошибок парсинга свободного ответа. Обе перестановки нужны, чтобы отличить предпочтение правильного ответа от предпочтения позиции A.

Reward model оценивает отдельно каждый ответ скаляром r(x,y). Разность r_good−r_bad определяет выбор, sigmoid разности задаёт условную Bradley–Terry вероятность. Масштаб награды не гарантирует калибровку. Одинаковый результат при перестановке здесь следует из архитектуры отдельных оценок; это не доказательство устойчивости к изменению совместного контекста.

## Что означает калибровка

Brier = среднее (p−y)². В сохранённых записях вероятность ориентирована на правильного кандидата, поэтому y=1; это алгебраически эквивалентно вероятности A с бинарной меткой правильности A. Хорошая точность и хорошая калибровка различны: уверенная ошибка штрафуется сильнее.

Для отдельного эксперимента 32 задачи используются только для подбора температуры T по neutral NLL, оставшиеся 32 — для оценки. p_T = sigmoid(logit(p)/T), T>0. Положительная температура не меняет знак логита и accuracy; она меняет уверенность. Диапазон T заранее ограничен [0.25,4]. Успех на этом маленьком тесте не означает калибровку на настоящих научных статьях или на другой модели.

## Статистическая единица

Есть 64 исходные задачи, пять оформлений и два порядка. 640 решений не являются 640 независимыми экспериментами. При bootstrap используется задача целиком; обе позиции объединяются внутри задачи. Сдвиг accuracy относительно neutral сохраняется в `style_sensitivity.json`. `temperature_calibration.json` относится только к 32 отложенным задачам; общая таблица сырого аудита использует все 64.

## Откуда данные и чему здесь не обучали

Это синтетические предпочтения с программными числовыми эталонами и явно заданной логикой доказательств. Они не являются разметкой экспертов. Готовые SFT/reward adapters взяты из предыдущей лаборатории; на новых оценочных парах их веса не обновляются. Здесь обучается только один скаляр температуры для каждого оценщика. Исходные контрактные задачи не используются.

## Как читать результат

Сначала сравните neutral accuracy с 0.5, затем частоту изменения решения при перестановке. Сопоставьте wrong_verbose с neutral и correct_verbose: симметрия контролей помогает понять направление стилевого влияния. Затем отдельно сравните raw/scaled Brier на отложенных задачах. Не выбирайте лучший стиль по тесту и не объявляйте его новым подтверждённым методом без нового набора данных.

Фактические значения находятся в `results/report.md` и JSON; до исполнения значения не подставляются. Отрицательный результат — например, нейтральный оценщик около случайного выбора — сохраняется и ограничивает применимость.

Упражнение: добавьте новое оформление без изменения числового содержания; сначала зафиксируйте гипотезу и отдельные задачи, затем проверьте, меняются ли решения. Не переиспользуйте текущие test-пары для подбора температуры.
